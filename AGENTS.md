# Project maintenance

- Treat the original competition code as reference material. Maintain a coherent NBA implementation with explicit provenance and documented changes.
- Keep the repository professional: concise documentation, meaningful names, reproducible commands, and no conversational transcripts or unverified performance claims.
- Maintain `paper/main.tex` as the technical manuscript. Update relevant sections alongside material changes to equations, feature definitions, data sources, parameter fitting, or evaluation.
- Distinguish proposed methods, implemented behavior, verified results, and unresolved choices. Do not present a working draft as a completed study.
- Keep the manuscript self-contained and compilable; document author and contributor changes accurately.
- Preserve private repository visibility unless the owner explicitly requests publication.
- Use free data and hosting within included allowances; no paid services or automatic paid overage.
- Preserve issued pregame forecasts when models are refitted or source data corrected.
